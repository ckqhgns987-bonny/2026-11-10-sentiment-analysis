# docs/03_frontend_logic.md - 프론트엔드 기능 및 DOM 제어 지침

## 1. 개요
Vanilla JavaScript (`public/app.js`)를 사용하여 사용자 입력 검증, 백엔드 API와의 Fetch 통신, 딩 상태 표시, 결과 렌더링 및 에러 처리를 구현합니다.

## 2. 상세 구현 요구사항
1. **입력 검증 (Form Validation)**:
   * 최소 5자 이상, 최대 1,000자 제한.
   * 미달 또는 초과 시 '분석하기' 버튼 비활성화 또는 에러 문구 표시.
2. **로딩 상태 (Loading State)**:
   * API 요청 시작 시 버튼 텍스트를 '분석 중...'으로 변경하고 로딩 스피너 활성화.
   * 중복 클릭 방지 (`disabled = true`).
3. **API 통신 (Fetch API)**:
   * POST `/api/analyze` 호출 (Body: `{ "text": "사용자 입력 문장" }`).
4. **결과 데이터 DOM 렌더링**:
   * `sentiment`: 긍정 / 부정 / 중립 중 알맞은 클래스와 텍스트 지정.
   * `confidence`: 백분율(예: 88%)을 프로그레스 바 형태 및 텍스트로 표시.
   * `reason`: AI 분석 이유 텍스트를 카드 내부 텍스트 상자에 삽입.
5. **오류 메시지 처리**:
   * API 응답 실패 시 하단에 Red 톤의 경고 토스트/알림 박스 출력 (예: "서버와 통신 중 오류가 발생했습니다. 잠시 후 다시 시도해주세요.").

## 3. 완료 기준 & 검증 기준 (Acceptance Criteria)
* [ ] 빈 값 또는 5자 미만 입력 시 분석 버튼 클릭이 차단되고 오류 메시지가 표시되는가?
* [ ] Fetch 응답을 받은 후 0.5초 이내에 UI 결과 창에 긍정/부정/중립, 신뢰도(%), 분석 이유가 바인딩되는가?
* [ ] 백엔드가 500 에러를 반환할 때 프론트엔드가 먹통이 되지 않고 오류 메시지가 UI에 노출되는가?
